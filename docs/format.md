# MOSS-Pocket 笔记库格式（版本 1）

本文档描述 MOSS-Pocket 在磁盘上怎么存数据，供审查和将来的兼容性参考。实现见 `crates/mp-core/src/`。

设计目标：

- **静态加密**：拿到数据目录的人，没有口令就读不出任何内容。
- **只信公开标准**：Argon2id、AES-256-GCM、SHA-256，全部用 RustCrypto 的纯 Rust 实现，不自己发明算法。
- **不丢数据**：任何一次写入要么完整落盘，要么保持原样；主文件坏了还能退回上一版。
- **不重写整个库**：每条笔记是一个文件；改密码只重写库头。

## 目录布局

便携模式，数据目录固定在 exe 旁边，名字是 `MOSS-Pocket-data`：

```
MOSS-Pocket-data/
  vault.json        明文库头
  index.enc         加密的条目索引（列表用，不含正文）
  notes/
    <笔记标识>.note      每条笔记一个加密文件
    <笔记标识>.note.prev 上一版备份
  blobs/
    <媒体标识>.blob      加密的媒体文件，分块存储
```

写入过程中的临时文件以 `.tmp` 结尾，正常情况下不会长期存在。

程序运行期间目录里还有一个 `.lock` 文件，用来保证同一时间只有一份程序在写这个库。它不加密，也不含任何内容，程序关闭后留着没有影响。

所有标识都是 16 个随机字节的十六进制表示，共 32 个字符，小写。程序在拼接路径前会校验标识的格式，损坏的索引不可能把读写引到目录外面。

## 密钥结构

库里有一个随机生成的 **32 字节主密钥**。所有内容都用它派生出来的子密钥加密，主密钥本身从不明文落盘，而是被「包装」后存进库头。

口令到主密钥分两步：

1. **密钥派生**：Argon2id，默认参数是内存 65536 KiB、迭代 3 轮、并行度 1，每个包装各用 16 字节随机盐，输出 32 字节的包装密钥。
2. **解包**：用包装密钥做 AES-256-GCM 解密，得到主密钥。

主密钥有两份包装，彼此独立：

| 包装 | 用的口令 | 用途 |
| --- | --- | --- |
| `password` | 用户密码 | 日常解锁 |
| `recovery` | 恢复密钥（16 字节随机量，排成 26 个 Base32 字符） | 忘记密码时解锁 |

改密码、换恢复密钥都只是换掉对应的那一份包装，笔记和媒体文件一个字节都不用动。

## 认证加密的绑定关系

每个加密文件除了密钥，还绑定了「它是什么、属于谁」，这些信息作为附加认证数据（AAD）参与校验。把一个文件的密文挪到另一个位置、或改写任何内容，都会解密失败。

**包装**（在 `vault.json` 里）：

```
明文 = 主密钥(32 字节) ‖ 库标识(UTF-8)
AAD  = "moss-pocket/wrap/v1|" ‖ 包装种类 ‖ "|" ‖ 库标识
```

明文里附带库标识，解开后会再核对一次，防止把别的库的包装拷过来。

**子密钥**：用途不同的密钥都从主密钥派生，互不通用。

```
子密钥 = SHA-256( 主密钥 ‖ "moss-pocket/v1|" ‖ 用途 ‖ "|" ‖ 库标识 ‖ "|" ‖ 名称 )
```

| 用途 | 名称 | 加密对象 |
| --- | --- | --- |
| `note` | 空 | 所有笔记文件 |
| `index` | 空 | 条目索引 |
| `blob` | 媒体标识 | 对应的媒体文件 |

**笔记和索引**的文件结构相同：

```
标识(4 字节) ‖ 随机数(12 字节) ‖ 密文 ‖ 认证标签(16 字节)
```

| 文件 | 标识 | AAD | 明文 |
| --- | --- | --- | --- |
| 笔记 | `MPN1` | `"moss-pocket/v1\|" ‖ note ‖ "\|" ‖ 库标识 ‖ "\|" ‖ 笔记标识` | 笔记的 JSON |
| 索引 | `MPI1` | `"moss-pocket/v1\|" ‖ index ‖ "\|" ‖ 库标识 ‖ "\|"` | 摘要数组的 JSON |

**媒体文件**分块加密，默认每块 1 MiB，可以按需解密任意一段（流式播放不用整份读进内存）：

```
文件头(20 字节) ‖ 第 0 块密文 ‖ 第 1 块密文 ‖ …
文件头 = "MPB1" ‖ 分块大小(u32 小端) ‖ 随机数前缀(4 字节) ‖ 原始长度(u64 小端)
```

每一块单独认证：

```
第 i 块明文长度 = min(分块大小, 原始长度 − i × 分块大小)
随机数 = 随机数前缀(4 字节) ‖ i(u64 小端)
AAD    = "moss-pocket/chunk/v1|" ‖ 库标识 ‖ "|" ‖ 媒体标识 ‖ i(u64 小端) ‖ 第 i 块明文长度(u64 小端)
```

同一把密钥下每块的随机数都不重复。AAD 里绑了块序号和明文长度，所以块不能被调换、截断或从别的文件拼接。

## 崩溃安全

写任何文件都走同一条路：

1. 把完整的新内容写进 `.tmp`，并要求操作系统落盘。
2. 如果旧文件存在，把它改名为 `.prev`。
3. 把 `.tmp` 改名顶上旧文件的位置。这一步失败就把 `.prev` 改回去。

任何时刻断电或崩溃，磁盘上都有至少一份完整的文件。读笔记时如果主文件解不开，会自动退回 `.prev`。

导入媒体是先写 `.tmp`、全部写完再改名；中途出错会把半成品删掉。

## 笔记的数据结构

笔记是 JSON，整体加密后存盘。要点：

- 标题不是单独的字段，取第一个非空文本块的第一行。
- 内容是块的数组，每块有独立的标识。块类型有：文本、图片、音频、视频、分割线。
- 文本块里有类型（段落、一到三级标题、项目符号、编号、引用）、正文，和行内样式区间。区间用的是**字符**下标，不是字节。
- `deleted_at` 有值表示在回收站。

## 回收站与清理

- 进回收站的笔记保留 30 天，到期后在下次解锁时彻底删除。
- 没有任何笔记引用的媒体文件算孤儿，解锁时清理。只要有一条笔记解不开，就不做任何清理，宁可多占空间也不误删。

## 这个设计防得住什么、防不住什么

**防得住**：数据目录被拷走、硬盘丢失、网盘账号泄露。没有口令或恢复密钥，别人只能看到一堆密文。

**防不住**，请知悉：

- **元数据**。条目的数量、每个媒体文件的大小、文件的创建修改时间是没有加密的。
- **本机上正在运行的恶意程序**。解锁期间明文和密钥都在内存里，同一用户权限下的恶意软件可以读取它们。离开电脑时请锁定。
- **内存交换和休眠文件**。明文可能被系统写进页面文件或休眠文件。对这方面有要求的话，请配合磁盘加密（如 BitLocker）使用。
- **弱口令**。派生函数只是让每次猜测变慢，挡不住「123456」这种口令。

## 版本与兼容

库头的 `version` 目前是 1。程序遇到比自己所知更新的版本会拒绝打开并提示升级，不会去改写它。字段只在确有必要时才增加，旧版本写出的文件新版本必须能读。
